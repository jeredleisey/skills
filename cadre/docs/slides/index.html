cadre

Agents with the discipline of a team

Jered Leisey  ·  2026-11-19

Welcome. Today I show a Claude Code plugin that I built, named cadre. It helps agents work like a team and not like a loose crowd. About 20 minutes of slides, then a live demo, then your questions.

The problem

  • One long agent session loses its context
  • Many agents change the same files
  • An agent's "done" is a claim, not proof
  • It is not clear what an agent may do alone
Most of you have seen these faults. A long session forgets the start of the task. Two agents edit one file and break each other. An agent says "done", but nobody checked. And it is hard to know which steps an agent may take without you.

The idea

The tracker is a GitHub issue or an Azure DevOps work item.

You talk to one agent, the orchestrator. It owns the outcome and splits the work into tickets. Each helper does one ticket in its own worktree, so helpers never share files. The tracker, a GitHub issue or an Azure DevOps work item, is the record.

The charter

  • The rules of a repo, stated once
  • Reviewed like code, in a pull request
  • Who merges, who deploys, what only a person may do
  • /cadre:setup writes it for you
Every repo has rules, but they often live in people's heads. The charter writes them in one file. The setup command opens a pull request for it, so your team reviews the rules like any other change.

A report is a claim

  1. The helper commits, then stops
  2. The orchestrator runs the tests itself
  3. It reads the diff for scope
  4. A separate reviewer reads the head commit
  5. It fixes each must-fix and should-fix before a merge
This is the verify loop. The helper says what it did, and that is only a claim. The orchestrator runs the tests again and reads the diff. A different agent reviews the head commit. A wrong claim costs more after a merge than before it.

Permissions: the ledger

  • Only you grant a permission, in your own session
  • One-way steps need a grant: merge, deploy, delete, force push
  • Guards (hooks) ask before a merge, a force push, or a push to the default branch. They always deny a helper
  • Not a security boundary. The branch policy of your repo is.
A one-way step is a step that a new commit cannot undo. For these, the orchestrator needs a grant that only you can write. Hooks ask you for the orchestrator and deny a helper with no prompt. Be clear: hooks slow an agent and stop a slip. Your branch policy is the real guard.

The tracker is the record

  • One issue holds the state: purpose, ledger, holder, checkpoints
  • A new session, a new machine, or another person resumes from it
  • One session holds a name at a time
The orchestrator keeps no private memory. If your session ends or Claude Code compacts your context, a new session reads the issue and continues. Only one session holds the orchestrator name at a time, so two sessions do not race.

A real example: these slides

  • I left for an appointment. My orchestrator kept working
  • It wrote tickets and ran a coder for the Windows prerequisites page and for this deck
  • It ran reviewers on two open pull requests and fixed their findings
  • It merged after green CI, with a grant from me
This deck is a cadre ticket. While I was away, the orchestrator wrote the tickets and started coders. Reviewers read the pull requests, and the orchestrator fixed their findings. It merged only after CI was green, and only because I had given it a grant.

Start small

  • /cadre:setup once: it writes the charter
  • /cadre:ticket <ticket> does one ticket
  • No orchestrator. A coder, a reviewer, one pull request that you merge
  • Then /cadre:orchestrate for many tickets
Do not start with the full system. Run the ticket command on one real ticket. You get a pull request and you merge it yourself. The command never merges or deploys. It needs a charter, so run setup once in the repo first.

Get ready

  • Windows: Git for Windows, Node 22 or later, Claude Code
  • The Azure CLI and its azure-devops extension
  • A personal access token in AZURE_DEVOPS_EXT_PAT
  • cadre.jeredleisey.com/how-to/prepare-a-windows-computer/

/plugin marketplace add jeredleisey/skills

/plugin install cadre@jeredleisey

The page on the screen lists each step and ends with a ready check. After you set the token, quit VS Code fully and start it again. After that, two commands install the plugin inside Claude Code. Try the install after the session if you do not have time now.
